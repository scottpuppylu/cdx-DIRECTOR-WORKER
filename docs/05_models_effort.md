# 05 模型與思考程度

依 Codex 介面提供的模型與該模型可用的 effort 選擇。工單記錄請求及實際執行的版本，建議不固定帳號方案或隨時間變化的型號。Codex App Server 使用啟動時的設定；原地換供應商後，舊 thread 恢復要看該版本的相容性。

| 工作 | 選擇原則 |
|---|---|
| 狀態查詢、列檔、交付格式整理 | 用機械工具完成，模型閱讀採低成本 |
| 單一模組或可重現小修正 | 用合適的標準模型與 effort，依測試調整 |
| 規格分歧、資料遷移、跨工作線整合 | 給足推理預算，要求獨立規格審查、下游驗收及回退 |
| 獨立 reviewer | 重視獨立輸入、完整 diff、可實測的唯讀權限，再選模型 |

在專案配置引用自訂 agent 時，它的模型與指示可個別選擇，沙箱與核准設定承接父線。需要不同權限時用獨立 root thread。輪數、額度和效能觀測記在 WORKER_LIMIT 與續航檔，發現兩輪沒有進展先追根因，避免用更高 effort 重複試錯。 [Codex subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents)

### 派工規劃

每批先列讀取、施工、獨立審查的工作範圍及依賴，同一工作樹採 Single Writer。用工單和沙箱決定能否分線，並列各線的模型、effort、checkpoint 與停工條件。
